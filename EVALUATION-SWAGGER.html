Known Issues

1 — POST without explicit ID returns 500

All three crnk-data-jpa services require the client to provide an explicit data.id in the request body when creating resources. Without it, JPA throws ids must be manually assigned before calling save(). This is expected crnk behavior. All services work correctly when IDs are provided — see the gateway's createOrder() for the correct pattern (mints ID before .create() call).

2 — Reverse relationship URL /account/{id}/orders returns 500

The Account.orders field is @Transient and not exposed as a JSON:API relationship endpoint. The correct approach is to use ?filter[account.id]=X on /order (as the gateway does), or the dedicated /account/{id}/relationships/orders endpoint. This is a design decision in the accounts-service codebase, not a library defect.

Final Verdict

YES — Library artifacts are working correctly

The crnk-framework-lts 4.0.0-lts.2 artifacts from Maven Central pass all core functional tests across four Spring Boot generations simultaneously. Wire-protocol cross-generation relationship resolution works correctly in both directions, across both the Jackson 2 and Jackson 3 wire formats, and through a BFF gateway that aggregates all three services.

Swagger/OpenAPI documentation was added to all four services using the appropriate library per generation: springfox 2.9.2 for Boot 2, springdoc-openapi 2.8.6 for Boot 3 and Boot 4. All four Swagger UI instances are live and serve OpenAPI JSON at the documented paths.

Two issues were observed and both are documented and non-blocking: (1) POST without a client-supplied ID is a known crnk-data-jpa constraint, handled correctly by the gateway's own code pattern; (2) the @Transient Account.orders field is not a JSON:API resource — the gateway correctly uses filter[account.id] instead, which is the right approach. Neither issue prevents correct operation of any documented endpoint.

Test methodology: full Docker stack (docker compose up), live HTTP calls via curl, raw response inspection. Test code: verify.ps1 in the project root. Swagger UI paths confirmed live in-browser. EVALUATION.md covers the full 44-test suite for core CRUD and wire protocol before Swagger addition.
